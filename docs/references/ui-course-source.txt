案例 C｜AI 情感陪伴产品（完整产品链路 · 主线案例）
方法论：数据 → MRD → BRD → PRD → 技术选型 → 开发 → 部署，每一步产出一份文档，后一份必须读取前一份的产物，不重复分析、不重复问用户。
C-0 项目初始化（共享上下文）
- 建 docs/（所有文档）、data/（数据），根目录留给代码
- 写进项目说明文件的共享上下文：产品方向、调研对象（Replika、Character.AI）、文档链路、存放规范
- 数据红线：所有结论、数字、引用必须来自真实采集的评论，不许编造；任何文档不展示可识别个人身份的信息
C-1 数据采集与洞察
安装 https://github.com/chusimin/AIPM-Skills 下的所有 Skills
调用 product-insight-miner 挖掘近 2 个月三平台上情感陪伴产品的用户痛点
→ 输出 markdown 分析报告
C-2 MRD（市场需求文档）
必含四部分：
1. 数据质量评估 —— 先说清这批数据能/不能分析什么（样本量、评分两极化、语言地区偏差、时间偏差、是否只代表留评用户）
2. 痛点聚类 —— 归为 3–5 个方向，每簇给名称、占比、说明 + 3–5 条真实原声引用
3. 需求优先级 —— P0/P1/P2 + 判断理由（出现频率、情绪强度、是否影响留存）
4. 竞品格局 —— Character.AI、Replika、Nomi、Kindroid、SillyTavern 等分别解决了什么、被抱怨什么、机会窗口在哪
C-3 BRD（商业需求文档）
1. 市场结论继承（让 BRD 可独立读懂）
2. 商业可行性：谁付费 / 怎么定价 / 成本结构（LLM 调用为主）/ 单位经济粗算
3. 明确结论：值得做 / 有条件地做 / 建议暂缓，三选一必须表态，不和稀泥
4. 关键风险：列出结论依赖的假设，指出哪个假设错了结论就会翻转，以及怎么验证
C-4 PRD（产品需求文档）
1. MVP 范围：V1 最多 3 个核心功能（从 P0 里挑）+ 「不做清单」，且不做清单要比要做清单更长更显眼
2. 页面 & 组件：具体到字段、按钮、空状态、异常态，让 AI 编码 agent 能直接照着实现
3. 设计交接：产品调性关键词、色彩方向、参考竞品的哪个设计
C-5 技术选型
要求 AI 先联网检索官方文档（不要只凭训练记忆），覆盖前端框架、样式方案、UI 组件库、大模型调用方式、部署平台；每项说明职责、为何选它、与替代方案的取舍、当前最新稳定版本 + 来源链接；原则是「最小够用」。
C-6 开发
- 严格遵守 PRD 范围，「不做清单」内一律不做；动手前先列页面结构确认
- 直接在项目根目录初始化前端，不新建 web/ 子目录
- 对话与记忆用最小方案，不引入向量检索：人设用系统提示词；短期记忆带最近若干轮；长期记忆用精简的「用户事实」键值数据每轮拼接
- API Key 单独放配置文件，告诉用户填哪个名字，用户自己填；模型层做成可替换结构
- 关键决策点（模型选择、产品命名）停下来确认
C-7 部署
Vercel + Supabase + AIHubMix

案例 E｜Cinematic 落地页（液态玻璃 + 视频背景）
一个高完成度的单页站 Build Prompt 范例，可直接复用其规格书写法：
- 技术栈（CDN 固定版本）：Tailwind CDN + React 18.3.1 + Babel Standalone + Framer Motion 11.11.17
- 字体：Instrument Serif（标题，永远斜体）+ Barlow（正文）；默认圆角覆盖为 9999px
- Liquid Glass 双变体：.liquid-glass（blur 4px，导航/标签/卡片）与 .liquid-glass-strong（blur 50px，主 CTA），均用 ::before + mask-composite: exclude 做渐变描边
- FadingVideo 组件：纯 rAF 驱动的淡入淡出，不用 CSS transition；FADE_MS=500、结束前 0.55s 提前淡出、手动实现 loop（关掉 loop 属性、监听 ended 重置）
- BlurText 组件：IntersectionObserver 10% 触发，按词 stagger 100ms，三段 keyframes 从 blur(10px) → blur(5px) → blur(0)
- 结构：Hero（120% 满屏视频 + 徽章 + 大标题 + 双 CTA + 两张数据卡 + 合作方）/ Capabilities（三张玻璃卡，各含图标 + 4 个 pill 标签 + 标题 + 描述）
💡 可迁移经验：把视觉规格写到「具体到 hex 色值、px 圆角、ms 时长、类名」的粒度，AI 才能一次性还原。

六、贯穿全程的方法论提炼
1. 一次只做一件事 —— 每个 prompt 只推进一小步，并明确写出「这一步不要做什么」
2. 先判断再动手 —— 技术选型阶段明确要求「先不要写代码」，让 AI 用大白话解释理由
3. 文档链路继承 —— 后一份文档必须读取前一份产物，不重复分析、不重复提问
4. 不做清单比要做清单更重要 —— MVP 收敛到 3 个功能以内，宁可少不要多
5. 规格写到可执行粒度 —— 具体到 hex 色值、px 尺寸、ms 时长、空状态与异常态
6. 真实数据、真实原声 —— 所有结论有据可查，不许编造，不展示个人身份信息
7. 沉淀为 Skill / claude.md —— 跑通一次的流程立刻封装复用，让能力可积累
8. 截图即 bug 报告 —— 用 PixPin 截图直接发给 Claude Code 定位问题
9. 密钥永远外置 —— config.json / .env，绝不入库
