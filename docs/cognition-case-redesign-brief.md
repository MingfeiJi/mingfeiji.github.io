# 个站改造说明：商业认知与案例证据链

## 目标

把“商业与 AI 认知”从一个独立展示模块，升级成整站的解释框架。

当前首页已经有很多强证据：旗舰中台、C 端闲聊 Agent、智能客服、硅基员工、原型工坊、知识库和 90 天驻场交付。但读者需要自己把这些证据和商业判断拼起来。改造目标是让用户一眼看到：

> 这些项目不是堆经历，而是在证明一套 AI 时代的商业判断。

核心表达：

> 我能把业务问题拆成 AI 系统，把系统跑成结果，把结果沉淀成组织能力。

## 信息架构调整

建议首页顺序调整为：

1. Hero：定位和硬指标
2. 关键成果：已经兑现的结果
3. 旗舰项目：出海内容增长 AI 中台
4. 商业与 AI 认知：认知与案例证据链
5. 项目档案：每个案例证明一条认知
6. 作品和原型：可点开验证
7. 履历、方法论、知识体系、技术栈、写作、90 天交付

其中第 4、5 两块是这次最重要的改造。

## 新章节：商业与 AI 认知

章节位置：`#cognition`，放在 `#flagship` 后、`#cases` 前。

章节开头建议文案：

> AI 时代的产品判断，不是“会不会用模型”，而是能不能把需求、差异化、组织效率、AI loop 和长期壁垒放在同一张图里判断。下面这些判断，不是概念摘抄，而是会改变项目动作的决策框架。

顶部强判断：

> AI 产品公司的核心问题，不是把工具做得更像工具，而是重新定义自己和模型公司的竞合关系：模型会吞掉通用能力，产品要长出场景、内容、关系、数据飞轮和商业自我造血。

## C 端 AI 产品判断链路

建议做成横向流程：

`需求强度 → 差异化 → 成本结构 → 反馈飞轮 → 长期壁垒`

每个节点下方说明：

- 需求强度：用户是否愿意持续付费
- 差异化：效果 / 获客 / 场景 / 生态
- 成本结构：token cost + marketing cost
- 反馈飞轮：user feedback → data → model/product
- 长期壁垒：内容生态、创作者网络、生成关系

这条链路要服务于一个目的：证明你看 AI 产品不是从模型能力出发，而是从商业闭环出发。

## 认知点位与案例映射

### 1. 需求决定收入，差异化决定利润

绑定案例：拟人化闲聊 Agent

页面链接：`/prototypes/chat-agent-arch.html`

证明逻辑：

- C 端 AI 产品不能只靠模型新鲜感。
- 情感陪伴/社交破冰的需求强度来自具体场景，而不是“能聊天”。
- 差异化来自长程记忆、人设一致、意图识别、防注入和付费节点设计。

证据 chips：

- 16 路意图
- 三路 RAG
- 防提示词注入
- 158 节点 / 184 连线
- 关键环节付费转化 +30%

建议卡片文案：

> 判断 C 端 AI 产品能否成立，不先问模型多强，而是问用户为什么持续付费、差异化来自哪里。拟人化闲聊 Agent 的价值，不是“能聊天”，而是把破冰、记忆、人设一致和付费节点做厚。

### 2. 工具层会被模型吞掉

绑定案例：出海内容增长 AI 中台

页面链接：

- `/prototypes/tripflow-arch.html`
- `/prototypes/tripflow-asset-library.html`
- `/prototypes/intent-47-journeys.html`

证明逻辑：

- 纯工具产品会越来越薄，因为通用能力会被模型持续内化。
- 所以不能把产品做成“全 AI 一键出片”这种通用工具。
- 真正更厚的是内容资产、创作者流程、合规审核、复盘数据和组织协作。

证据 chips：

- 毙掉“全 AI 一键出片”
- 毙掉“自动养号”
- 500 素材/周
- 990 发布/周
- 100 万+ 播放/周
- 23 项埋点 Schema

建议卡片文案：

> 模型会吞掉通用工具层，所以我在内容中台里没有追“一键出片”，而是把灵感、资产、创作、审核、剪辑、发布、复盘组织成可持续增长系统。

### 3. 链式协作会被球形协作替代

绑定案例：原型工坊 / Vibe Coding 课程 / Skill Workshop

页面链接：

- `/prototypes/`
- `/prototypes/vibecoding-class.html`
- `/prototypes/skill-workshop.html`

证明逻辑：

- 传统产品协作是产品、设计、前端、后端、测试逐段转译。
- AI-native 团队要求每个人直接输出可运行产物。
- 你的原型工坊、课程和 Skill 体系证明你已经在用这种方式生产。

证据 chips：

- 14 个可交互过程文件
- 172 份过程文档
- 20+ 高保真原型
- Vibe Coding 课程
- Skill Workshop
- 整站 Agent 构建

建议卡片文案：

> AI-native 协作不是多用几个工具，而是把产品经理从“写文档等排期”变成“直接交付可运行结构”。原型工坊就是我的球形协作证据。

### 4. AI 系统必须有 harness / evaluator / loop

绑定案例：智能客服小 V / 多模态审核体系 / 旗舰中台埋点

页面链接：

- `/prototypes/cs-agent-arch.html`
- `/prototypes/tripflow-arch.html`

证明逻辑：

- AI 系统不能只看 demo 效果。
- 必须有评测集、badcase、埋点、人工兜底和成本监控。
- 这对应面试里提到的 creation system harness 和 evaluator。

证据 chips：

- 30 类意图
- 80% 重复问题自动化
- 满意度 68%→84%
- 5000+ 多模态审核评测集
- 23 项埋点 Schema
- Langfuse tracing

建议卡片文案：

> 企业 AI 系统不是“跑通一次”，而是要能持续变好。harness 负责承载能力，evaluator 负责判断版本是否真的变好，badcase 和埋点让系统进入可迭代状态。

### 5. AI 改造必须由 owner 躬身入局

绑定案例：90 天驻场交付 / 蓝图签字机制 / 飞轮分工矩阵

页面链接：`#engagement`

证明逻辑：

- 第三方改造企业有结构性限制。
- 如果业务 owner 不拥有指标、数据和流程维护权，AI loop 就会断。
- 你的蓝图签字、责权利设计、业务变化归运营维护，都是在解决这个问题。

证据 chips：

- 业务蓝图签字
- 四层转型组织
- 业务变化归运营
- 技术稳定归工程
- 运营自维护手册
- 90 天移交节奏

建议卡片文案：

> AI 转型不是交付一个工具，而是让业务 owner 拿回迭代权。我的 90 天交付目标不是项目结束，而是项目组撤了以后，系统还能自己长。

### 6. 中层转译会被压缩，两层结构更快

绑定案例：AI-native 团队带教 / 旗舰中台组织协作

页面链接：`#flagship` 或 `#logbook`

证明逻辑：

- AI-native 团队不能有太多慢的转译层。
- 未来组织更像“目标 owner + 闭环个体”。
- 你在项目里带教 UI、开发、实习生、正岗产品，让每个人用 Agent 和 Vibe Coding 直接产出。

证据 chips：

- 3 UI + 5+ 开发
- 3 实习生 + 1 正岗产品
- 人人用 Agent
- 人人 Vibe Coding
- 日站会
- 反馈分诊

建议卡片文案：

> 两层组织不是没有协作，而是减少转译损耗。目标 owner 定义方向，闭环个体直接贡献可运行产物，中间层只保留必要的接口文档和评测标准。

## 旗舰案例新增块：商业判断与取舍

建议放在旗舰案例的约束/权衡模块前后。

标题：

> 为什么我先毙掉两个伪需求

正文：

> 进场第一件事不是上工具，而是判断什么不该做。“全 AI 一键出片”和“自动养号”看起来性感，但前者容易把复杂链路误判为单点生成问题，后者会撞上平台合规和账号风险。真正值得做的，是可持续的内容增长链路：灵感 → 资产 → 创作 → 审核 → 剪辑 → 发布 → 复盘。  
>  
> 这背后的商业判断是：工具层会变薄，通用生成能力会被模型吞掉；但内容资产、创作者流程、合规经验、复盘数据和组织协作，会越跑越厚。

- 避免新增大面积紫色，防止跟现有风格混成单一科技感
