# AI 产品架构师 / FDE 面试作品集设计规格

日期：2026-08-03  
页面路径：`/interview/`  
目标仓库：`MingfeiJi/mingfeiji.github.io`

## 1. 背景与目标

现有首页拥有丰富的项目、方法论、知识库、写作和技术证据，但同时承担简历、案例库、个人百科、咨询服务页和实验室入口等多种职责。面试官需要自行筛选信息，无法在短时间内形成清晰的录用判断。

新版页面定位为“面试决策引擎”，服务 AI 产品架构师 / Forward Deployed Engineer 岗位。页面要帮助面试官完成三层判断：

1. 30 秒内理解候选人的定位、差异化和最强结果。
2. 3 分钟内看完一个完整旗舰案例，确认产品设计与业务落地能力。
3. 10 分钟内通过原型、架构图和辅助案例验证真实性与能力广度。

## 2. 用户与核心任务

### 主要用户

- 招聘经理：判断岗位匹配度、业务影响和个人职责。
- 产品负责人：判断产品思考、信息架构、交互设计和指标体系能力。
- 技术或 AI 负责人：判断系统理解、Agent/RAG/评测体系及跨团队协作能力。

### 核心用户任务

- 快速回答“纪鸣飞是谁、适合解决什么问题”。
- 分辨已兑现结果、在途目标和候选人个人贡献。
- 看懂一个复杂 AI 产品如何从业务问题演化为产品与系统方案。
- 打开可运行原型或架构材料验证陈述。
- 低成本发起联系并获取完整简历。

## 3. 产品形态

采用“面试决策引擎”，而不是案例画廊或 AI 对话首页。AI 分身、知识库、写作和完整原型库继续作为二级能力存在，但不进入主判断路径。

页面为独立路由 `/interview/`，不覆盖现有首页。它使用独立布局和样式命名空间，避免影响现有 150+ 静态页面。

## 4. 信息架构

### 顶部导航

导航最多五项：

1. 首页
2. 旗舰案例
3. 项目案例
4. 方法与原型
5. 关于我

导航右侧保留高优先级“联系我”按钮。移动端折叠为简洁菜单，不展示章节编号轨道或主题面板。

### 页面结构

1. **Hero：定位与最强证明**
   - AI 产品架构师 / FDE
   - 价值主张：把复杂 AI 能力变成可运行、可衡量、可移交的业务系统
   - 四个已兑现指标
   - 主 CTA：“3 分钟看旗舰案例”
   - 次 CTA：“联系我 / 获取完整简历”

2. **能力判断条**
   - 产品判断
   - 系统架构
   - 业务落地
   - 驻场交付
   - 每项用一句结论和一个证据锚点表达

3. **旗舰案例：出海内容增长 AI 中台**
   - 项目背景与业务规模
   - 关键问题与现实约束
   - 用户研究与核心洞察
   - 信息架构与用户旅程
   - 产品方案与系统架构
   - 关键决策及取舍
   - 已兑现结果与在途目标
   - 个人职责、团队协作与可验证产物

4. **辅助案例**
   - 智能客服“小 V”
   - 制造业数字化转型
   - 每个案例只保留“问题—决策—结果—证据”四部分

5. **产品设计证据**
   - 用户研究
   - 信息架构
   - 用户旅程
   - 高保真原型
   - 指标、埋点与评测
   - 每一项链接到现有可验证材料

6. **FDE 工作方式**
   - 诊断
   - 共创
   - 交付
   - 验证
   - 移交
   - 强调业务现场、双轨指标、badcase 闭环和运营/工程分工

7. **履历与外部背书**
   - 三段递进式转型经历
   - 集团级战略奖、内训师、专栏和大会嘉宾等背书

8. **联系与下一步**
   - 邮箱联系
   - GitHub
   - 获取完整简历
   - 不提供虚假的简历下载按钮；当前仓库没有正式简历文件，因此“获取完整简历”使用邮件联系

## 5. 内容规则

- 所有结果必须标记为“已兑现”或“在途目标”，两者不得混排。
- 每个关键数字必须能够关联到具体案例和责任边界。
- 每个案例必须明确“我负责什么”，避免只描述团队成果。
- 首屏只保留四个最强指标，不展示完整指标墙。
- 技术名词只在支持产品决策或系统可行性时出现。
- 知识库、藏书阁、全部写作、课程、完整技术栈和咨询服务移出首页主路径。

## 6. 视觉设计

采用 Apple 编辑式暗色产品页风格，但不复制 Apple 资产或页面结构：

- 纯黑和近黑背景，大面积留白。
- 超大无衬线标题与高对比正文。
- 蓝紫液态背景作为低亮度氛围层，不能抢夺文字注意力。
- 悬浮玻璃导航使用轻薄模糊、细边框和大圆角。
- 卡片主要依靠排版、间距和轻微透明度建立层级，减少描边、粒子和发光。
- 视觉重点始终依次为：定位、结果、案例决策、证据入口。

页面不提供主题切换。单一视觉身份有利于面试官记忆，也降低加载和认知成本。

## 7. 交互设计

### 水波交互

- 桌面端鼠标划过产生中等强度冷蓝细波。
- 点击产生两层扩散涟漪。
- 水波 Canvas 位于内容层下方，设置 `pointer-events: none`。
- 移动端触摸产生单次涟漪，不持续追踪手指以控制功耗。
- 限制设备像素比、同时存在的波纹和生成频率。
- `prefers-reduced-motion: reduce` 下停用连续追踪，只保留静态背景。

### 页面反馈

- 顶部阅读进度展示页面完成度。
- 旗舰案例入口明确标注“约 3 分钟”。
- 证据链接统一使用“查看原型 / 查看架构 / 查看旅程”动词，不使用抽象标题。
- 卡片悬停仅做轻微抬升和高光，不做 3D 倾斜。
- 键盘焦点可见，所有功能可通过键盘访问。
- 外部材料新标签页打开，并明确使用外链符号。

## 8. 技术结构

- 新建独立 Astro 页面：`src/pages/interview/index.astro`。
- 新建专属布局或组件，使用 `interview-` 前缀隔离样式。
- 复用现有项目内容、原型链接和公开数据，不引入数据库或后台。
- 水波逻辑独立为可测试模块或专属组件，不改变当前首页主题行为。
- 不加载首页的 Three.js 粒子球、知识图谱或多重 iframe。
- 保留 Astro 静态输出，兼容 GitHub Pages 和 Vercel。

## 9. 响应式与性能

- 桌面目标宽度：内容最大宽度约 1200px，文本阅读宽度不超过 760px。
- 移动端目标宽度：360–430px，首屏价值主张和主 CTA 无需横向滚动。
- 移动端导航、指标和案例步骤改为单列。
- 首屏不加载非必要 iframe、Three.js 或大型背景资源。
- 动画只使用 `transform`、`opacity` 和 Canvas 绘制，不触发布局抖动。
- 页面无 JavaScript 时仍能阅读全部核心内容和打开证据链接。

## 10. 验收标准

### 内容

- 首屏明确显示目标岗位、价值主张、四个已兑现结果和两个行动入口。
- 旗舰案例覆盖背景、问题、洞察、方案、取舍、结果、职责和证据。
- 已兑现结果与在途目标在视觉和文案上清晰分离。

### 交互

- 鼠标划过和点击水波在桌面端可见且不阻挡按钮。
- 触屏、键盘和减少动态效果模式可正常使用。
- 所有站内锚点、项目链接、邮箱和 GitHub 链接有效。

### 质量

- Astro 构建成功。
- 桌面与移动端完成浏览器验证。
- 首屏和旗舰案例无控制台错误。
- 新页面不会改变现有首页及其他静态路由。

## 11. 发布方式

- 在现有 `agent/site-redesign` 分支开发。
- 提交到现有 GitHub PR，保持 `/interview/` 为独立页面。
- 发布 Vercel 预览供确认。
- 用户确认后再决定是否合并 PR 或将该页面升级为正式首页。
