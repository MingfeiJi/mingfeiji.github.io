# 手机访问与交互适配

本轮以已发布的 `839f79c1a073b7ac360703806a7b399e43e3273c` 为基线，优化首页的手机阅读、三维地图和曜黑玻璃。保留三种皮肤和现有作品、简历、知识体系内容。

## 产品行为

- 手机导航收敛为姓名、3D 作品、目录；完整目录在两列面板中展开，选中项目后自动收起，支持 Escape。首屏提供职业概览和地图入口，手机隐藏原有邮箱展示表单。
- 手机、触屏与节流网络默认显示东京实景首帧；点击探索或场景按钮才加载 Three.js 和对应模型。提供独立的「完成浏览」入口恢复页面滑动，加载失败可重试。未使用的场景不下载。
- 地图按钮至少 44px；限制渲染像素密度，按交互请求单帧重绘，页面后台或地图离屏时停止重绘。手动浏览模式下，离屏会退出地图交互。
- 曜黑玻璃直接显示本站 JPEG 首帧（31,366 bytes），移除这套皮肤的背景 iframe。手机默认静态，主题面板可主动开启动效；减少动态效果、节省流量或 2G 模式保留静态。桌面普通模式在页面完成加载并空闲后播放本站 MP4。
- 视频离开首屏、页面后台或切走皮肤时暂停。移动端降低大面积毛玻璃滤镜开销，文字使用系统字体；文章知识图谱离屏时不做力导向计算。
- 修复水波主题在初生波纹上可能产生负半径而抛错的问题；触摸结束后不继续保持鼠标悬停动画状态。

## 模型资产与可复现命令

原始 GLB 继续保留。新资源位于 `public/models/atlas/compact/`，使用 gltfpack 1.3 的 meshopt 压缩和 16 位位置量化；没有启用网格简化。Three.js 使用已有依赖内的 MeshoptDecoder，无外部解码 CDN。

```sh
# 在临时工具目录安装 gltfpack@1.3 后，对三个原始文件分别执行：
gltfpack -i public/models/atlas/tokyo.glb -o public/models/atlas/compact/tokyo.glb -cc -vp 16
gltfpack -i public/models/atlas/paris.glb -o public/models/atlas/compact/paris.glb -cc -vp 16
gltfpack -i public/models/atlas/earth.glb -o public/models/atlas/compact/earth.glb -cc -vp 16
```

| 模型 | 原始 bytes | 压缩 bytes | 下降 |
| --- | ---: | ---: | ---: |
| 东京 | 16,109,008 | 1,708,220 | 89.4% |
| 巴黎 | 8,958,284 | 1,011,328 | 88.7% |
| 地球 | 543,588 | 317,152 | 41.7% |

东京首帧为压缩模型实际渲染截图，WebP 12,636 bytes。模型来源及 OpenStreetMap 署名延续前一版记录。压缩参考：[meshoptimizer / gltfpack](https://github.com/zeux/meshoptimizer/tree/master/gltf)。

## 单次受控慢网对比

2026-10-29，在相同浏览器 390×844 视口下，通过仅供验收的本地服务器施加 **1.6 Mbps 总下载限速、每请求 150ms 延迟、no-store**，每版本各一次。HTML/CSS/JS 使用 gzip。固定普通动效偏好，不施加 CPU 限速。以下资源量是顶层 Performance Resource Timing 记录之和，不含 HTML 导航和 iframe 内部子资源，因此不是网站完整流量账单。

| 指标 | 已发布基线 | 手机优化候选 |
| --- | ---: | ---: |
| 首屏阶段资源请求 | 86 | 12 |
| 首屏阶段资源传输量 | 3,574,430 bytes | 309,151 bytes |
| 字体请求 | 76 | 1 |
| FCP | 1,632ms | 1,772ms |
| 东京模型开始加载至可交互 | 80,750ms | 10,000ms |

候选版首屏不下载 GLB 或背景 MP4。首帧完成约 1,774ms。FCP 没有显示改善，核心收益是后续字体流量、模型下载等待和手机默认 GPU 工作减少。背景 MP4 为用户主动开启后的额外 685,149 bytes，不计入手机默认首屏。

这些数字为受控浏览器样本，不代表真实手机 Safari/微信、蜂窝网络、CDN 冷缓存或低端设备帧率。尚未做真实 iPhone/Android 的连续触控、发热和内存测试。最终水波半径保护补丁只改变少量脚本字节，不改变测量中的请求策略和模型资产。
