## 一、背景

### 1.1 业务上下文

当前个站不是普通简历页，而是一座已经积累了大量可运行产物的“个人数字档案馆”：包含 AI 产品、20+ 高保真原型、文章、知识图谱、藏书阁、数字分身、WebGL 实验和三段 AI 转型经历。它的真实价值很高，但首页同时承担简历、作品集、方法论、知识库、实验室、内容归档和获客落地页等多种职责，导致首次访问者需要先理解网站，才能理解“纪鸣飞是谁”。

本次翻新不重做内容资产，而是重新编排叙事和视觉：用一个更像“AI 产品建筑师 / Vibe Coding 实践者”的个人品牌入口，把人、方法、过程和作品连接起来；保留现有深度内容，通过清晰路由让不同访客快速进入适合自己的阅读路径。

### 1.2 现状资产盘点

| 资产 | 当前规模/状态 | 翻新价值 |
|---|---|---|
| 首页 | 12 个长章节、13 个顶部入口 | 内容完整，但首次访问负担高 |
| 视觉主题 | 星空、动态水墨、曜黑玻璃、赛博全息、月白极简，共 5 套 | 个性鲜明，但品牌识别被拆散，维护成本高 |
| 内容页面 | 首页、文章、笔记、图谱、藏书阁、原型目录等 9 个 Astro 路由 | 可重组为清晰的内容产品矩阵 |
| 可运行原型 | `public/prototypes` 中 26 个 HTML 原型 | 是最强的“可验证能力”证据，应前置 |
| 互动能力 | AI 数字分身、Three.js 星场、知识图谱、粒子实验室 | 可保留为差异化体验，需做性能门禁 |
| 图片资产 | 仅 `og-cover.png` 与桌宠头像 | 缺少真人感、现场感和可信度，需要个人照片体系 |
| 技术底座 | Astro 5 静态站 + CSS 主题变量 + Three.js | 足够支撑 V1，无需重写框架 |
| 发布体系 | GitHub Pages/现有线上代理，计划接 Vercel、Supabase | 适合建立 Preview → Review → Production 流程 |

### 1.3 当前痛点

1. **首屏角色不够鲜明**：文字和指标很多，但缺少个人照片与一个强视觉锚点，访问者先看到“系统”，后看到“人”。
2. **内容主线被 12 个章节稀释**：成果、旗舰、认知、档案、产品、作品、履历、方法、知识、能力、写作、驻场并列，无法快速判断优先级。
3. **5 套主题各自成体系**：主题切换有趣，但视觉语言过多，组件差异和背景特效增加维护、性能和测试成本。
4. **Vibe Coding 没有成为一级叙事**：现有内容中有大量可运行原型、Agent 工作流、Skill 工程和自动化证据，但分散在“极客能力”“方法论”“作品”等章节，未形成清晰的方法品牌。
5. **个人照片缺位**：无法展示演讲、驻场、工作、课程、生活等真实场景，降低信任感和人物记忆。
6. **行动入口分散**：看作品、了解方法、体验产品、邮件联系等 CTA 分布在多个章节，缺少明确的主路径和次路径。
7. **性能存在隐患**：多主题背景 iframe、Three.js、卡片指针效果和长页面同时存在；需要按设备、主题、可见区域延迟加载。
8. **部署与数据闭环未标准化**：Vercel Preview、正式域名、联系表单、订阅数据、分析指标和 Supabase 权限策略尚未形成统一方案。

### 1.4 目标用户与访问任务

| 访客 | 第一问题 | 希望完成的动作 | 优先内容 |
|---|---|---|---|
| 招聘方/业务负责人 | 他是否真的做过复杂 AI 产品？ | 5 分钟判断能力并联系 | 结果、代表案例、履历、本人照片 |
| 创业者/企业客户 | 他能否帮团队完成 AI 转型？ | 了解方法、查看交付物、预约沟通 | 90 天交付、方法论、案例证据 |
| 产品/设计/工程同行 | 他的 Vibe Coding 到底怎么做？ | 学习流程、体验原型、收藏文章 | Vibe Coding OS、构建日志、工具栈 |
| 内容读者/学生 | 有哪些课程、文章和资料？ | 按主题检索并持续关注 | 写作、课程、知识图谱、藏书阁 |
| 潜在协作者 | 是否适合共同做项目？ | 理解价值观、工作方式和当前方向 | About、Now、工作流、GitHub |

## 二、收益与指标

### 2.1 目标收益

本次翻新优先解决“访问者理解效率”和“真实可信度”，其次才是视觉惊艳。三主题和动效的判断标准是是否帮助内容，而不是是否展示更多技术。

| 指标 | 现状 | v1.0 目标 | 测量方式 |
|---|---|---|---|
| 首屏身份理解率 | 待基线 | 5 秒测试中 ≥ 80% 能复述“AI 产品架构师 + Vibe Coding 实践者” | 5 人可用性测试 |
| 核心作品到达率 | 待基线 | 首页访问中 ≥ 25% 进入一个案例/产品页 | Vercel Web Analytics 或 PostHog 事件 |
| 联系 CTA 点击率 | 待基线 | 首页访问中 ≥ 3% 点击联系/合作 | `cta_contact_click` |
| Vibe Coding 专区到达率 | 当前无一级入口 | 首页访问中 ≥ 20% 进入专区 | `nav_vibecoding_click` |
| 移动端 Lighthouse Performance | 待基线 | ≥ 90 | CI 中运行 Lighthouse |
| Accessibility | 待基线 | ≥ 95；键盘可访问；动效尊重 reduced-motion | Lighthouse + 人工检查 |
| LCP | 待基线 | 75 分位 < 2.5 秒 | Vercel Speed Insights |
| CLS | 待基线 | < 0.1 | Vercel Speed Insights |
| 首页导航入口 | 13 个 | 桌面一级入口 6 个以内；移动端 5 个核心入口 | DOM/设计验收 |
| 首页核心章节 | 12 个 | 6 个核心章节以内 | 页面结构验收 |
| 公开真人照片 | 0 张 | 首页 3–5 张，About/案例累计 8–12 张 | 资产清单验收 |
| 主题数量 | 5 套 | 3 套共享组件主题 | 主题回归测试 |

### 2.2 衡量节奏

- **D+7**：检查构建、性能、路由、移动端、图片加载和 CTA 埋点；完成 5 秒理解测试。
- **D+14**：观察首页到案例、Vibe Coding、联系入口的点击分布，调整首屏文案和卡片顺序。
- **D+30**：复盘访客来源、停留深度和转化；决定是否增加 Supabase 订阅、Build Log 自动化或英文版。

### 2.3 GO/NO-GO 验收标准

- [ ] 首页在 390px、768px、1440px 三个宽度无横向溢出、遮挡或不可读内容。
- [ ] 三主题所有核心页面可读，主题切换后不闪白、不重载正文、不破坏滚动位置。
- [ ] 首屏只包含一个主 CTA 和最多两个次 CTA，角色、成果、照片三者同时可见。
- [ ] 所有个人照片完成授权确认、EXIF 清理、WebP/AVIF 转换、尺寸与 alt 文本填写。
- [ ] 首页移动端 Performance ≥ 90，LCP < 2.5 秒，CLS < 0.1。
- [ ] Vercel Preview 构建通过后才能合并 `main`；生产发布可回滚到上一版本。
- [ ] Supabase 若启用，匿名用户只能新增自己的联系/订阅记录，不能读取全表。
- [ ] GitHub 仓库和 Vercel 环境中不存在硬编码密钥或私人照片原图。

## 三、解决方案

### 3.1 总体策略：从“长简历星球”变成“人的构建现场”

```text
[第一眼：真人 + 一句话定位]
              ↓
[可信结果：3 个已兑现数字]
              ↓
[精选案例：看得见、点得开、能运行]
              ↓
[Vibe Coding OS：展示如何从意图到上线]
              ↓
[构建现场：照片 + Build Log + 工具链]
              ↓
[思考与知识：文章 / 图谱 / 藏书阁]
              ↓
[合作 CTA：招聘 / 顾问 / 共创]
```

核心判断：默认首页不再承担全部内容的完整展示，而承担“分发”。深内容迁移到 Work、Vibe Coding、Thinking、About 四个一级页面；旧路由保留，避免历史链接失效。

### 3.2 三种风格合并方案

现有 5 套主题收敛为 3 套，组件结构完全一致，只切换设计 token、背景媒介和局部动效。用户不是进入三套不同网站，而是在同一品牌中选择三种观看情绪。

#### 风格 A：曜黑构建舱（默认主题）

**合并来源**：星辰大海 + 曜黑玻璃 + 赛博全息。

**品牌含义**：强调“正在构建的 AI 产品现场”，是首页、Vibe Coding 和可运行产品的默认表达。

| 设计项 | 规划规格 |
|---|---|
| 主色 | Obsidian `#07080B`、Ivory `#F5F3EE`、Electric Cyan `#7DD3FC` |
| 点缀 | Signal Violet `#A78BFA`，只用于流程节点和链接状态 |
| 字体 | 中文标题 Noto Serif SC；英文展示 Instrument Serif；正文 LXGW WenKai/系统字体；代码 JetBrains Mono |
| 表面 | 两级液态玻璃：导航/标签 blur 12px；主 CTA/重点案例 blur 32–48px |
| 圆角 | 胶囊 CTA 9999px；内容卡 20px；小标签 9999px |
| 背景 | 单一轻量星云/WebGL 层；赛博扫描线只在 Vibe Coding 交互区短时出现 |
| 动效 | 进入动效 420–680ms；指针视差 ≤ 8px；不做持续高频闪烁 |
| 适用 | 首页、精选作品、Vibe Coding、AI 产品体验 |

#### 风格 B：水墨手记

**合并来源**：动态水墨 + 已下架宣纸主题的编辑排印语言。

**品牌含义**：把方法论、思考和中国式工作经验呈现为可阅读的“研究手记”。

| 设计项 | 规划规格 |
|---|---|
| 主色 | Paper `#F5F1E8`、Ink `#171717`、Seal `#9E2B25` |
| 字体 | Noto Serif SC / 宋体系为主；英文小标题 JetBrains Mono |
| 表面 | 纸张纹理透明度 ≤ 4%；墨线分隔；不使用玻璃卡片 |
| 圆角 | 2–6px，接近纸张与编辑部栏目的直角语言 |
| 动效 | 墨迹扩散只用于章节开场；正文无漂浮动画 |
| 图片 | 黑白/低饱和现场照，保留一处朱砂色标记 |
| 适用 | 方法论、文章、履历长文、课程内容、知识体系 |

#### 风格 C：月白作品册

**合并来源**：月白极简，并吸收瑞士编辑与作品集网格。

**品牌含义**：用于招聘方和合作方快速审阅项目，是最清晰、克制、可信的阅读模式。

| 设计项 | 规划规格 |
|---|---|
| 主色 | Warm White `#FAFAF8`、Graphite `#18181B`、Cobalt `#1D4ED8` |
| 字体 | 无衬线为主，数字和标签用 JetBrains Mono |
| 网格 | 12 栏桌面、6 栏平板、4 栏移动；8px spacing 基线 |
| 表面 | 白底、细发丝线、轻阴影；不使用背景视频和 3D 星场 |
| 圆角 | 0–8px；项目封面保持方正 |
| 动效 | 150–240ms，主要是淡入、位移和焦点反馈 |
| 适用 | Work、项目案例、简历、数据成果、打印/PDF 导出 |

#### 三主题映射表

| 现有主题 | v1.0 去向 | 保留内容 | 停止维护内容 |
|---|---|---|---|
| 星空 `cosmos` | 合入曜黑构建舱 | 星空氛围、蓝紫品牌色 | 独立主题入口 |

### 3.3 信息架构与页面规划

#### 一级导航（桌面 6 项）

1. **Home**：人物、结果、精选作品、Vibe Coding 摘要、联系。
2. **Work**：案例、可运行产品、原型、项目档案。
3. **Vibe Coding**：方法论、工作流、工具链、Build Log、模板。
4. **Thinking**：文章、方法论、知识图谱、藏书阁。
5. **About**：履历、人物照片、价值观、Now、合作方式。
6. **Contact**：页面内主 CTA；移动端可作为固定底部按钮。

原型、图谱、藏书阁、文章不再全部挤在顶栏，放入 Work/Thinking 的二级导航和首页快捷入口。

#### 首页六段结构

| 顺序 | 区域 | 关键内容 | 目标动作 |
|---|---|---|---|
| 1 | Hero / 人物入口 | 真人主视觉、角色定位、当前方向、主 CTA | 看精选作品 |
| 2 | Proof Strip / 可信结果 | 3 个已兑现结果 + 1 条外部认可 | 建立信任 |
| 3 | Selected Work / 精选作品 | 3 个代表案例，每个含封面、角色、问题、结果、产物 | 进入案例页 |
| 4 | Vibe Coding OS | 7 步闭环 + 3 个构建证据 + 最新 Build Log | 进入专区 |
| 5 | Human Layer / 人的现场 | 演讲、驻场、工作台、生活照片 + 个人叙事 | 了解 About |
| 6 | Thinking & Contact | 最新文章、知识入口、合作 CTA | 阅读或联系 |

#### Work 页面

- 顶部只回答“做过什么、做到什么程度”。
- 筛选：AI Platform、Agent、Content System、Transformation、Prototype。
- 每张项目卡统一 6 个字段：问题、角色、周期、动作、量化结果、可验证产物。
- 旗舰案例使用独立详情页，结构为：背景 → 决策 → 系统 → 过程 → 结果 → 复盘 → 相关产物。
- 原有 26 个 HTML 原型进入“Prototype Archive”，支持主题/年份/成熟度筛选。

#### Vibe Coding 页面（新增一级专区）

这是本次翻新的内容重点，不做简单工具清单，而是展示一套可复用的个人构建系统。

```text
Intent 意图
  ↓
Spec 规格与不做清单
  ↓
Prototype 可运行原型
  ↓
Agent 编排与 Skill
  ↓
Evaluate 截图/测试/Badcase
  ↓
Ship GitHub → Vercel
  ↓
Compound 文档、模板、知识库继续复利
```

页面模块：

- **Vibe Coding Manifesto**：3 条原则——用可运行产物说话、一次只推进一个闭环、评测与文档让能力复利。
- **Operating Loop**：7 步交互流程图，每一步可展开查看真实文件、Prompt、截图或代码。
- **Build With Me**：选择一个真实项目，按时间线展示“从一句话到上线”的 8–12 个关键提交。
- **Agent Stack**：Codex/Claude Code、Skills、MCP、浏览器操作、评测、GitHub、Vercel、Supabase 的职责图。
- **Vibe Coding Cases**：至少 4 个案例：内容增长 AI 中台、灵感引擎/工作台、AI 桌宠、个人站本身。
- **Artifact Gallery**：PRD、流程图、高保真原型、测试报告、构建日志、发布记录。
- **Reusable Kit**：公开可分享的模板、Checklist、Prompt 规范和 Skill 入口。
- **Now Building**：当前正在构建的 1–3 件事，按月更新。

#### Thinking 页面

- 合并公开写作、方法论、课程、图谱和藏书阁入口。
- 首页只展示 3 篇精选；完整目录支持主题与内容类型筛选。
- 使用“水墨手记”为主要视觉模式，长文阅读默认关闭高成本背景动效。

#### About 页面

- 不是简历全文搬运，而是“人、经历、工作方式、生活感”的组合。
- 内容顺序：人物引言 → 三段经历 → 关键转折 → 工作现场照片 → 价值观 → 当前关注 → 合作方式。
- 提供 PDF 简历下载，但网页先给出可快速扫读的结构。

### 3.4 首页核心视觉线框


### 3.5 模块拆解

#### 模块 A：人物化 Hero

**核心思路**：先让人记住纪鸣飞，再让人理解系统。

- 主标题控制在 18–28 个中文字符，表达“AI 产品落地 + Vibe Coding”。
- 主视觉使用 4:5 或 3:4 真人半身照，不使用纯头像圆形裁切。
- 照片旁显示一张可更新的 `Now Building` 小卡，只放 1 个当前项目和更新时间。
- 结果数字从 4–5 个收敛到 3 个，全部标记“已兑现”或“目标”。
- 主 CTA：“看精选作品”；次 CTA：“看我的 Vibe Coding 系统”。
- 现有 AI 小飞桌宠从首屏视觉竞争中降级，延迟到用户滚动后出现。

#### 模块 B：可信结果与代表案例

**核心思路**：每个数字必须能落到一个案例，每个案例必须能点开一个产物。

- 结果条使用“指标 + 业务语境 + 案例链接”，不只展示大数字。
- 首页精选 3 个案例，建议：出海内容增长 AI 中台、智能客服小 V、Vibe Coding 原型系统。
- 案例封面由真实界面截图、架构图和现场照片组合，不统一使用抽象 AI 插画。
- 卡片 hover 只展示“查看案例”，不做大角度 3D 倾斜。

#### 模块 C：Vibe Coding OS

**核心思路**：把“会用工具”升级成“有系统、有证据、有复利”。

- 7 步流程图作为视觉主轴。
- 每一步提供一个真实产物类型：Brief、PRD、Prototype、Agent Config、Test、Preview、Skill。
- 首页显示摘要；完整页面支持展开和复制公开模板。
- 代码/Prompt 示例只展示 8–16 行，避免成为教程墙。
- Build Log 初期使用构建时生成的静态 JSON；不为实时感引入不必要后端。

#### 模块 D：个人照片叙事

**核心思路**：照片不是装饰，而是分别证明“是谁、在哪里做过、如何工作、生活气质”。

建议照片清单：

| 编号 | 照片类型 | 建议数量 | 页面位置 | 构图/用途 |
|---|---|---:|---|---|
| P1 | Hero 主肖像 | 1 | 首页首屏 | 4:5 半身，视线有方向，右侧或左侧留文案空间 |
| P2 | 工作台/编程现场 | 1–2 | Vibe Coding | 屏幕、手、桌面和本人同时出现，证明构建过程 |
| P3 | 演讲/课程现场 | 1–2 | 首页可信层、About | 有环境和听众，不只截大头 |
| P4 | 驻场/会议/白板 | 1–2 | 旗舰案例、About | 展示 FDE 与业务现场 |
| P5 | 团队协作 | 1 | About | 需确认其他人物肖像授权，可模糊或裁切 |
| P6 | 生活/旅行/海边 | 1–2 | About 尾部 | 提供温度，与现有 GitHub 海边头像形成呼应 |
| P7 | 设备与手稿细节 | 2–3 | Vibe Coding/章节过渡 | 作为横向纹理图或内容分隔 |

照片处理规范：

- 原图放私有素材目录，不直接提交；公开导出放 `public/images/profile/`。
- 主视觉生成 AVIF + WebP 两份；列表图 1600px 长边以内；缩略图 800px 长边以内。
- 单张首屏图目标 ≤ 180KB，其他图目标 ≤ 250KB；必须声明宽高，避免 CLS。
- 上线前清除 GPS、设备、拍摄时间等 EXIF；确认同框人物授权。
- alt 文本描述场景与信息，不写“图片”或堆关键词。
- 三主题可使用同一照片，通过 CSS 调整色彩；不维护三份重复原图。

#### 模块 E：导航、主题切换与阅读模式

**核心思路**：主题是观看方式，导航是任务入口，两者不互相打扰。

- 桌面顶栏 6 项以内；移动端使用菜单 + 固定联系按钮。
- 主题切换器由 5 项收敛为 3 项，名称与说明可见，保存用户选择。
- 首次访问默认曜黑构建舱；文章/Thinking 可自动建议水墨，但不强制切换。
- 提供“减少动效”快捷项，并尊重系统 `prefers-reduced-motion`。
- 当前页面/章节提供清晰 active 状态；右侧 12 段 rail 在首页移除或缩为 6 段。

#### 模块 F：联系与转化闭环

**核心思路**：不让访问者猜“怎么合作”。

- 三种合作入口：全职/项目合作、AI 转型顾问、内容/课程共创。
- 联系表单字段控制在 5 个：姓名、联系方式、合作类型、问题描述、期望时间。
- V1 可先使用 `mailto` + 复制邮箱；V1.1 再接 Supabase。
- 如果接 Supabase，前端不使用 service role key；写入通过受限 API/Edge Function，增加速率限制和验证码。
- 提交成功显示下一步和预计回复时间，不只显示“成功”。

#### 模块 G：性能、可访问性与工程治理

**核心思路**：让技术感来自完成度，而不是运行负担。

- Astro 岛屿化：静态内容保持零客户端 JS，互动组件按需加载。
- Three.js 只在曜黑主题且设备能力满足时加载；月白和水墨不加载 WebGL。
- 背景特效从多个 iframe 合并为一个主题感知组件；页面不可见时暂停动画。
- 卡片指针跟随只在精确指针设备启用；触摸设备不注册 mousemove。
- 图片使用 `<picture>`、响应式 `srcset`、懒加载和明确尺寸。
- 建立统一 design tokens，主题仅覆写 token；禁止继续新增散落的主题选择器。
- 每个 PR 自动运行 Astro build、链接检查、基础可访问性和 Lighthouse 预算。

### 3.6 技术方案

| 层 | v1.0 方案 | 选择理由 | 暂不选择 |
|---|---|---|---|
| 框架 | 保留 Astro 5 | 现有内容和静态路由完整，迁移风险最低 | 不切 Next.js，仅为部署不值得重写 |
| 样式 | CSS variables + 分层 token + 组件样式 | 现有主题底座可复用，三主题容易统一 | 不引入重型 UI 库覆盖现有个性 |
| 动效 | CSS/WAAPI 为主，复杂章节再评估 GSAP | 控制体积和可访问性 | 不在全站使用连续滚动编排 |
| 3D | 复用 Three.js，但设置主题/设备/可见性门禁 | 保留差异化极客气质 | 月白、水墨默认不加载 |
| 内容 | Astro Content Collections | 现有文章体系已稳定 | V1 不引入 CMS |
| 图片 | 本地优化后的 AVIF/WebP；Vercel CDN 分发 | 简单、版本化、可预览 | V1 不用 Supabase Storage 管公开展示图 |
| 部署 | GitHub → Vercel Preview → `main` Production | 每个 PR 有可审阅链接 | 不直接在本地覆盖生产 |
| 数据 | V1 无后端；V1.1 联系/订阅接 Supabase | 先验证是否需要持久化 | 不为 Build Log/主题偏好上数据库 |
| 分析 | Vercel Web Analytics + Speed Insights；必要时 PostHog | 先看流量、性能、核心事件 | 不采集敏感输入和完整会话 |

实施时所有版本号与 SDK 用法必须再查官方文档确认，不在规划阶段锁死易变化的版本。

### 3.8 异常与降级

| 场景 | 处理 |
|---|---|
| WebGL 不支持或低性能设备 | 自动切换静态渐变/纹理背景，正文功能不受影响 |
| 用户减少动效 | 停止视差、数字滚动、循环动画，保留必要状态反馈 |
| 图片加载失败 | 保留固定比例占位和主题色背景，alt 文本可理解 |
| Supabase 不可用 | 联系表单提示改用邮件，不丢失用户已输入文本 |
| Build Log 数据失败 | 显示最后一次构建的静态快照 |
| 老路由访问 | 保留原路由或 301 到新内容，不返回空白页 |
| 第三方演示失效 | 案例保留截图、说明和 GitHub/归档链接 |

### 5.2 v1.0 不做什么

- ❌ 不重写成 Next.js：当前 Astro 足以满足静态作品集和内容站需求。

- ❌ 不把 26 个原型全部重新设计：先统一目录与封面，逐步升级重点案例。
- ❌ 不做实时 GitHub activity feed：先用构建时静态数据，避免 API 配额和客户端暴露。
- ❌ 不在首版接复杂账号系统：个站访问无需登录。
- ❌ 不用 Supabase 管主题偏好：浏览器本地存储已经足够。
- ❌ 不上传未经筛选的私人相册：只提交公开导出图，原图与 EXIF 不进仓库。
- ❌ 不保留 5 套并列主题：兼容旧键，但 UI 只显示 3 套。
- ❌ 不让每个章节都拥有独立背景特效：背景媒介统一管理。
- ❌ 不在首屏自动播放有声视频：如使用视频，必须静音、可暂停、有静态 poster。
- ❌ 不为了“科技感”增加更多漂浮粒子、霓虹边框和无意义 3D 倾斜。

## 八、风险与依赖

| 风险/依赖 | 影响 | 缓解 |
|---|---|---|
| 照片未及时提供或授权不清 | Hero 和 About 无法完成人物化 | 先完成构图占位；只上线授权清单内照片；同框他人裁切/模糊 |
| 现有内容过多，迁移范围失控 | 开发周期被内容编辑拖长 | v1 只迁移 3 个案例和首页摘要，其他保留旧路由 |
| 主题合并导致历史页面样式回归 | 文章、图谱、原型出现可读性问题 | 共享 token；建立核心路由 × 三主题回归矩阵 |
| Three.js/iframe 特效影响性能 | 移动端 LCP、耗电和滚动卡顿 | 设备/可见性/主题门禁；月白和水墨禁用 WebGL |
| Vibe Coding 内容泄露项目机密 | 影响公司/客户信息安全 | 逐案例脱敏；只用已公开数据；建立可公开字段清单 |
| 量化数字“已兑现/目标”混淆 | 损害可信度 | UI 中显式区分；案例页给来源与时间范围 |
| Supabase 权限配置错误 | 联系数据泄露或被滥用 | V1 不强依赖；V1.1 使用 RLS、服务端写入、速率限制、审计 |
| GitHub 当前由 `tonyj233` 管理员账号推送 | 操作者显示与个人品牌账号不同 | 在仓库设置正确 commit author；长期决定是否切回 `MingfeiJi` CLI |
| UI Skill 原始表格缺失 | 无法逐条复用用户指定规则 | 实施前补充飞书截图/原文件；当前规划保留映射占位 |
| 旧 GitHub Pages 与 Vercel 并存 | 域名、SEO、环境变量和 API 地址混乱 | 明确唯一生产域名；设 canonical；迁移后统一重定向 |
